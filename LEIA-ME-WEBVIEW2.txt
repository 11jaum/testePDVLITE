ADEGA PDV - WEBVIEW2 V2
========================

CORREÇÃO PRINCIPAL
------------------
A versão anterior usava o Node.js instalado no Windows durante "npm ci".
No seu computador isso usou Node 24.19.0 e o npm tentou recompilar
better-sqlite3 com node-gyp, passando a exigir Python.

A versão V2 muda o processo:

1. NÃO usa o Node instalado no Windows.
2. Baixa Node.js 22.20.0 x64 oficial em uma pasta local ".tools".
3. Instala dependências com "--ignore-scripts".
4. Testa better-sqlite3 de verdade antes de continuar.
5. Se o SQLite não carregar, para antes de gerar um app quebrado.
6. Baixa um .NET 8 SDK LOCAL usando o instalador oficial da Microsoft.
7. Compila o launcher WebView2 self-contained.
8. Copia o Node portátil para "dist\runtime\node.exe".
9. Faz um segundo teste do SQLite dentro da própria pasta "dist".

RESULTADO
---------
Depois da compilação:

dist\
  AdegaPDV.exe
  *.dll do launcher self-contained
  app\
    server.js
    node_modules\
    database\
    ...
  runtime\
    node.exe
  data\
  logs\

O computador que executar a pasta "dist" não precisa ter:
- Node.js instalado;
- Python;
- npm;
- .NET Desktop Runtime.

Ele precisa do Microsoft Edge WebView2 Runtime.
Windows 11 e a maioria das instalações atuais do Windows 10 já possuem.

COMO GERAR
----------
1. Extraia o ZIP em uma pasta normal, por exemplo:
   C:\AdegaPDV-WebView2-v2

2. Feche qualquer versão do AdegaPDV que estiver aberta.

3. Execute:
   PREPARAR-WEBVIEW2.bat

4. Na primeira execução, deixe a internet conectada.

5. Aguarde até aparecer "PRONTO".

6. Abra:
   dist\AdegaPDV.exe

BANCO ATUAL
-----------
O gerador NÃO apaga nem substitui automaticamente seu banco atual.

Depois de gerar "dist", execute:
COPIAR-BANCO-ATUAL.bat

e informe a pasta da versão atual do seu AdegaPDV.

O banco será copiado para:
dist\app\database\adega.db

Faça sempre backup do adega.db antes de substituir qualquer versão.

SE DER ERRO
-----------
O processo grava:
PREPARAR-WEBVIEW2.log

Envie esse arquivo para diagnóstico.

IMPORTANTE
----------
A V2 foi feita especificamente para evitar o erro anterior:

node-gyp -> find Python -> Could not find any Python installation to use

Você NÃO precisa instalar Python por causa do AdegaPDV.

V2.1 - CORREÇÃO POWERSHELL
--------------------------
Corrigido o erro em que $PSScriptRoot podia chegar vazio em algumas formas
de execução do PowerShell. O gerador agora resolve a própria pasta usando
$MyInvocation e, como último recurso, a pasta atual.


V2.2 - CORREÇÃO DO TESTE FINAL
------------------------------
Corrigido o teste 7/7. A versão anterior executava JavaScript inline com "node -e",
e o PowerShell/cmd alterava as aspas do código, causando:
SyntaxError: Unexpected token ':'

Agora o teste final grava um arquivo JavaScript temporário dentro da pasta
"dist\app", executa esse arquivo com o Node portátil e remove o arquivo depois.
Isso evita qualquer problema de escaping de aspas.


V2.3 - MIGRAÇÃO DE BANCO CORRIGIDA
----------------------------------
A cópia simples do arquivo adega.db foi substituída por uma migração SQLite
consistente usando o próprio better-sqlite3 da versão WebView2.

Use:
MIGRAR-BANCO-ATUAL.bat

O utilitário:
1. procura automaticamente o adega.db antigo;
2. aceita também o caminho completo do arquivo;
3. cria backup do banco atual da versão WebView2 antes de substituir;
4. usa SQLite backup em vez de simples Copy-Item;
5. valida o banco de destino;
6. mostra contagem de registros de tabelas principais.

Feche a versão antiga e a versão WebView2 antes de migrar.


V2.4 - CORREÇÃO DE RESOLUÇÃO DO BETTER-SQLITE3
-----------------------------------------------
Corrigido o erro:
Cannot find module 'better-sqlite3'

O migrador fica na raiz do pacote, enquanto node_modules fica em dist\app.
Agora o MIGRAR-BANCO.js usa createRequire() apontando explicitamente para
dist\app\package.json, garantindo que better-sqlite3 seja carregado da
instalação correta.

Também foi adicionado PRAGMA integrity_check após a migração.

2. INSTALADOR SETUP.EXE
-----------------------
Depois de gerar a pasta dist, execute:

GERAR-INSTALADOR.bat

O script procura o Inno Setup 6. Se não encontrar e o Windows possuir winget,
tenta instalá-lo automaticamente.

installer\output\AdegaPDV-Setup-1.0.0.exe

[2] gerar instalador limpo.

Se incluir seu banco no Setup, não compartilhe esse instalador com terceiros.

---------------------
Para gerar um ZIP de atualização:

CRIAR-PACOTE-ATUALIZACAO.bat

Ele cria um pacote que NÃO contém:
- banco de dados;
- backups;
- cache/sessão;
- logs.

O instalador também nunca sobrescreve um adega.db já existente.

Antes de uma atualização pelo Setup, um backup do banco existente é criado em:

app\backups\antes-atualizacao

4. DESINSTALAÇÃO
----------------
O Inno Setup registra o Adega PDV normalmente em "Aplicativos instalados"
do Windows.

Os dados criados pelo usuário não são empacotados como arquivos normais do
instalador; isso reduz o risco de apagar o banco durante uma atualização.

V3.0 / ADEGA PDV 1.1.0 - ESTABILIDADE
======================================

NOVO: INSTÂNCIA ÚNICA
---------------------
O launcher usa Mutex do Windows.
Se tentar abrir AdegaPDV.exe duas vezes, a segunda execução exibe:
"O Adega PDV já está aberto neste computador."

NOVO: BACKUP AUTOMÁTICO DIÁRIO
------------------------------
Ao iniciar o Adega PDV:
- se existir app\database\adega.db;
- e ainda não existir backup do dia;

é criado:
app\backups\automaticos\adega_YYYY-MM-DD.db

São mantidos os 30 backups automáticos mais recentes.

NOVO: MENU SISTEMA
------------------
Na parte superior do aplicativo existe "Sistema" com:
- Criar backup agora
- Restaurar backup...
- Abrir pasta de backups
- Recarregar interface
- Tela cheia
- Sobre / Diagnóstico

Atalho para backup manual:
Ctrl + Shift + B

NOVO: RESTAURAÇÃO DE BACKUP
---------------------------
"Sistema > Restaurar backup..." permite escolher um arquivo .db.

Antes da restauração:
1. o banco atual recebe um backup;
2. o servidor Node é encerrado;
3. o banco escolhido substitui o banco atual;
4. o servidor é iniciado novamente;
5. a interface é recarregada.

Se o servidor não conseguir iniciar após a restauração, o launcher tenta
voltar automaticamente ao banco anterior.

NOVO: SOBRE / DIAGNÓSTICO
-------------------------
Mostra:
- versão do Adega PDV;
- servidor ativo/inativo;
- endereço local;
- Node embutido/sistema;
- versão do WebView2;
- caminho e tamanho do banco;
- último backup;
- pasta do aplicativo.

LOG ROTATIVO
------------
logs\server.log passa a rotacionar ao atingir aproximadamente 5 MB.
O log anterior é mantido como server.log.1.
